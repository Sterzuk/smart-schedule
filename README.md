# Умное расписание

MVP веб-сервиса для школьного расписания: чат-бот, который понимает вопросы обычным языком, и подробная таблица уроков с комбинируемыми фильтрами.

Проект полностью работает локально и не использует платные AI-сервисы. Запросы разбирает предсказуемый парсер на TypeScript, а данные для чата и фильтров берутся из одной базы через backend API.

## Что умеет приложение

- **Главная страница** с описанием сервиса, работающим мини-чатом и переходами к расписанию.
- **Чат-бот**:
  - понимает дни недели, слова «сегодня» и «завтра», предметы, кабинеты, номера уроков и время;
  - ведёт историю сообщений в рамках текущей сессии;
  - показывает индикатор обработки и понятные сообщения об ошибках;
  - возвращает карточки найденных уроков и подсказки для следующего запроса.
- **Расписание**:
  - полная неделя и переключение по дням;
  - поиск по предмету;
  - фильтры по классу, дню и времени начала;
  - все фильтры комбинируются и применяются на backend;
  - таблица для компьютера и карточки для телефона;
  - skeleton, пустое состояние и состояние ошибки с повтором запроса.
- **Данные**: расписание класса 10-Б — 1 класс, 37 уроков, 20 предметов, 5 учебных дней. Преподаватели в данных и интерфейсе отсутствуют.
- **API**: валидация входных данных, единый формат успешных и ошибочных ответов.

## Быстрый старт

### Требования

- Node.js 20 или новее (проект проверен на Node.js 26);
- npm;
- свободные порты `3000` (frontend) и `3001` (backend).

### 1. Установка корневых зависимостей

```bash
npm install
```

### 2. Переменные окружения

Создайте локальные конфигурации **до подготовки базы**: Prisma читает `DATABASE_URL` из `backend/.env`.

**PowerShell:**

```powershell
Copy-Item backend/.env.example backend/.env
Copy-Item frontend/.env.example frontend/.env.local
```

**bash / macOS / Linux:**

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env.local
```

Значения по умолчанию подходят для локального запуска:

```dotenv
# backend/.env
DATABASE_URL="file:./dev.db"
PORT=3001
CORS_ORIGIN="http://localhost:3000,http://127.0.0.1:3000"
```

```dotenv
# frontend/.env.local
NEXT_PUBLIC_API_URL=http://localhost:3001/api
```

### 3. Установка зависимостей приложений и базы

```bash
npm run setup
```

Команда `setup` последовательно запускает установку в `backend/` и `frontend/`, генерирует Prisma Client, применяет миграцию и заполняет базу демо-данными.

### 4. Запуск в режиме разработки

```bash
npm run dev
```

Будут запущены оба приложения:

- приложение: <http://localhost:3000>
- API: <http://localhost:3001/api>
- health-check: <http://localhost:3001/api/health>

Остановить оба процесса можно через `Ctrl+C`.

### 5. Production-сборка

Убедитесь, что `frontend/.env.local` создан **до сборки**: значение `NEXT_PUBLIC_API_URL` встраивается в клиентский бандл.

```bash
npm run build
npm start
```

## API

Базовый URL: `http://localhost:3001/api`.

### Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Статус backend |
| `GET` | `/schedule` | Вся неделя |
| `GET` | `/schedule/filter` | Фильтрация расписания |
| `GET` | `/schedule/options` | Классы, предметы, дни и номера уроков для фильтров |
| `GET` | `/schedule/:id` | Один урок по идентификатору |
| `POST` | `/chat` | Запрос к чат-боту |

### Параметры `/schedule/filter`

| Параметр | Формат | Поведение |
| --- | --- | --- |
| `day` | `Понедельник` … `Пятница`, `Пн` … `Пт` | Точный день |
| `className` | `10-Б`, `10б`, `10 б` | Нормализованный класс |
| `subject` | строка | Точное название предмета без учёта регистра |
| `search` | строка | Поиск подстроки в названии предмета |
| `room` | строка | Частичное совпадение по кабинету |
| `startAfter` | `HH:mm` | Начало строго позже времени |
| `startBefore` | `HH:mm` | Начало строго раньше времени |
| `endAfter` | `HH:mm` | Окончание строго позже времени |
| `endBefore` | `HH:mm` | Окончание строго раньше времени |
| `lessonNumber` | целое `1…12` | Номер урока |

Все переданные фильтры объединяются через **AND**.

Примеры:

```http
GET /api/schedule/filter?className=10-%D0%91&day=%D0%9F%D0%BE%D0%BD%D0%B5%D0%B4%D0%B5%D0%BB%D1%8C%D0%BD%D0%B8%D0%BA
GET /api/schedule/filter?className=10-%D0%91&startAfter=12%3A00
```

Более читаемый вид:

```text
GET /api/schedule/filter?className=10-Б&day=Понедельник
GET /api/schedule/filter?search=физика
GET /api/schedule/filter?subject=Физика&day=Среда
```

### Успешный ответ расписания

```json
{
  "success": true,
  "lessons": [
    {
      "id": 1,
      "day": "Понедельник",
      "dayOrder": 1,
      "lessonNumber": 1,
      "startTime": "08:30",
      "endTime": "09:15",
      "subject": "Разговор о важном",
      "className": "10-Б",
      "room": "105"
    }
  ],
  "total": 8,
  "appliedFilters": {
    "className": "10-Б",
    "day": "Понедельник"
  },
  "options": {
    "classes": ["10-Б"],
    "subjects": ["..."],
    "days": ["Понедельник", "Вторник", "Среда", "Четверг", "Пятница"],
    "lessonNumbers": [1, 2, 3, 4, 5, 6, 7, 8]
  }
}
```

Массив `lessons` в примере сокращён до одного урока; фактические `id` зависят от текущей базы.

`GET /api/schedule/:id` возвращает `{ "success": true, "lesson": { ... } }`.

### Запрос к чату

```http
POST /api/chat
Content-Type: application/json

{
  "message": "Какие уроки у 10-Б в среду начинаются после 13:00?"
}
```

Ответ:

```json
{
  "success": true,
  "reply": "Вот уроки в среду для 10-Б. Начало после 13:00. Найдено 2 урока.",
  "lessons": [],
  "total": 3,
  "appliedFilters": {
    "day": "Среда",
    "className": "10-Б",
    "startAfter": "13:00"
  },
  "suggestions": ["..."],
  "intent": "find_lessons"
}
```

Поле `lessons` в примере сокращено до `[]`; фактически API возвращает массив уроков в том же формате, что и расписание.

Поддерживаемые интенты: `find_lessons`, `greeting`, `help`, `thanks`, `off_day`, `unrecognized`.

Успешный `POST /api/chat` возвращает HTTP **200**.

### Ошибки

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте корректность отправленных данных",
    "details": ["День должен быть одним из: Понедельник, Вторник, Среда, Четверг, Пятница"]
  }
}
```

Коды ошибок: `VALIDATION_ERROR`, `NOT_FOUND`, `BAD_REQUEST`, `INTERNAL_ERROR`.

- пустое сообщение чата или некорректный параметр фильтра — HTTP 400;
- несуществующий урок — HTTP 404;
- внутренняя ошибка — HTTP 500.

## Чат-бот: примеры запросов

```text
Покажи расписание 10-Б на понедельник
Какие уроки у 10-Б в среду начинаются после 13:00?
Что заканчивается после 14:00?
Когда математика у 10-Б?
Уроки физики в пятницу
Что идёт в кабинете 301?
Какой предмет шестым уроком у 10-Б?
Что завтра у 10-Б?
```

Особенности парсера:

- «математика» объединяет алгебру, геометрию и вероятность со статистикой;
- «физра» и «физкультура» находят физическую культуру;
- «сегодня» и «завтра» вычисляются по локальной дате; в выходной возвращается ответ, что занятий нет;
- время без минут (`после 13`) трактуется как `13:00`;
- диапазон «с 10:00 до 12:00» фильтрует по началу внутри диапазона;
- регистр, буква «ё», лишние пробелы и варианты записи класса (`10-Б`, `10б`, `10 б`) нормализуются.

История чата хранится только в состоянии текущей страницы и не требует авторизации. Внешние AI-API не используются.

## Деплой

Проект разделён на два приложения, поэтому используется два сервиса:

- **frontend** — Vercel (Next.js);
- **backend** — Render (NestJS + Prisma + SQLite). Vercel не подходит для backend: там нет постоянной файловой системы для SQLite.

### Backend на Render

В репозитории есть blueprint `render.yaml`:

1. Откройте <https://dashboard.render.com/select-repo?type=blueprint> и выберите репозиторий.
2. Render создаст сервис `smart-schedule-api` из `render.yaml`.
3. Дождитесь первого деплоя и проверьте `https://<service>.onrender.com/api/health`.

На бесплатном тарифе диск эфемерный, поэтому миграция и seed выполняются при каждом старте. Для этого расписания это безопасно: данные доступны только для чтения и полностью воссоздаются из `backend/prisma/seed.ts`.

### Frontend на Vercel

1. Откройте <https://vercel.com/new> и импортируйте тот же репозиторий.
2. В настройках проекта укажите **Root Directory**: `frontend`.
3. Добавьте переменную окружения:
   - `NEXT_PUBLIC_API_URL = https://<service>.onrender.com/api`
4. Нажмите **Deploy**.

После публикации добавьте адрес Vercel в `CORS_ORIGIN` сервиса Render (вместо `*`), например:

```dotenv
CORS_ORIGIN="https://smart-schedule.vercel.app"
```

и перезапустите backend.

## Переход на PostgreSQL

Схема Prisma не использует SQLite-специфичных типов, поэтому модель данных переносится без изменений.

Для локального MVP:

1. Измените провайдер в `backend/prisma/schema.prisma`:

   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```

2. Задайте строку подключения в `backend/.env`:

   ```dotenv
   DATABASE_URL="postgresql://user:password@localhost:5432/smart_schedule?schema=public"
   ```

3. Сгенерируйте клиент и примените схему. Для быстрого локального перехода можно использовать:

   ```bash
   npm run db:push --prefix backend
   npm run db:seed --prefix backend
   ```

   Для полноценной работы с миграциями создайте отдельную PostgreSQL-миграцию. Текущая миграция в `backend/prisma/migrations/` содержит SQLite-синтаксис и не должна применяться к PostgreSQL. Сохраните её копию вне папки `migrations/` и удалите SQLite-миграцию из истории перед созданием новой:

   ```bash
   cd backend
   npx prisma migrate dev --name init_postgres
   ```

   В production используйте PostgreSQL-миграцию с `npx prisma migrate deploy`.

`class-validator` и DTO от СУБД не зависят. При переходе на PostgreSQL также стоит заменить строковые поля времени и дня на нативные типы/enum, если это потребуется в следующей версии.

## Возможные проблемы

### Порт уже занят

Измените `PORT` в `backend/.env`. Если порт backend меняется, обновите `NEXT_PUBLIC_API_URL` в `frontend/.env.local` и `CORS_ORIGIN` в `backend/.env`, затем перезапустите приложение и пересоберите frontend.

### Frontend показывает «Сервер не отвечает»

1. Убедитесь, что backend запущен: `http://localhost:3001/api/health`.
2. Проверьте, что `NEXT_PUBLIC_API_URL` указывает на правильный порт.
3. Проверьте `CORS_ORIGIN`: origin frontend должен быть в списке.
4. После изменения `NEXT_PUBLIC_API_URL` пересоберите frontend.

### База пустая или данные повреждены

```bash
npm run db:seed
```

Команда удаляет уроки и заново загружает демо-расписание с проверкой конфликтов.

### Prisma не может скачать движки

Скрипты `db:*` запускаются через `backend/scripts/prisma-cli.cjs`. В среде без доступа к `binaries.prisma.sh` можно заранее положить:

- `backend/.prisma-engines/schema-engine.exe`;
- `backend/.prisma-engines/query_engine-windows.dll.node`.

Обёртка подхватит их автоматически. На обычной машине с интернетом Prisma работает стандартным способом, без этих файлов.

### `npm` не запускается в PowerShell

Если политика выполнения блокирует `npm.ps1`, используйте `npm.cmd`:

```powershell
npm.cmd run dev
```

## Ограничения MVP

- демонстрационные данные, без интеграции с реальной школьной системой;
- нет авторизации и ролей;
- расписание доступно только для чтения;
- чат не использует LLM и понимает заданные шаблоны языка, а не произвольные рассуждения;
- история чата не сохраняется между перезагрузками страницы;
- учебная неделя — понедельник–пятница.
